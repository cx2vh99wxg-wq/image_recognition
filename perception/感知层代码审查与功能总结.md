## 二、本次发现并修复的真实缺陷（局部正确性）

### 缺陷：ISP 参数字典整体错位一格（off-by-one）

文件：`perception/csrc/isp_params.c`

- **根因**：`DESC_TABLE`（参数真值表）用指定初始化器 `[ISP_PARAM_X]` 以 **id 值（1 基）** 直接下标；但 `isp_param_table[]` 与 `isp_param_lookup()` 却用 `&DESC_TABLE[ISP_PARAM_X - 1]` / `&DESC_TABLE[id - 1]` 去减 1 引用。两者索引约定不一致，导致**每个参数都指向了 id-1 的字典项**。
- **现象（修复前实测）**：
  - `isp_param_lookup(ISP_PARAM_MODE=0x01)` 返回空项（name=NULL）；
  - `isp_param_lookup(ISP_PARAM_BLC=0x02)` 返回了 **mode** 的字典项（name="mode"）；
  - `isp_param_clamp(ISP_PARAM_BLC, 200)` 被按 mode 的合法区间 `[0,3]` 裁成 **3**，直接把合法值破坏。
- **修复**：把两处引用统一为 1 基（去掉 `- 1`），并在 `isp_params.c` 内加了注释说明约定。
- **回归保障**：新增 `test/test_isp_params.c`（已纳入 Makefile 与运行序列），覆盖 14 个参数的 id/name/min/max/def 完全匹配、非法 id 返回 NULL、clamp 合法保持/越界裁剪。修复后该测试全 PASS。

> ⚠️ 该缺陷此前无任何测试覆盖（`isp_params` 虽编译进工程但没人单测），所以一直潜伏。现已补上。

## 四、你需要重点关注的事项

### 1. 职责红线（务必守住）
- **A 只碰** `perception/**` 与 A 起草的 `common/{driving_types.h, log.h}`。
- **不碰** B 的 `common/{driving_config.h, shm_ipc.h, csrc/shm_ipc.c}`、`planning/`；**不碰** C 的 `fpga/`、`control/`、`fpga_regmap.h`。
- 红绿灯结论：**识别灯色 = A**，但**红停绿行决策 = B**（你只负责把 `TrafficLightResult` 交给 B）。

### 2. 待 B / C 交付才能闭环（非 A 责任）
- B 需提供 `common/csrc/shm_ipc.c`（共享内存读写），否则板端 `perception_main` 无法链接运行。
- 若 B 要经共享内存消费 `LaneMarkResult` / `ZebraResult` / `TrafficLightResult`，需要 B 在 `driving_config.h` 新增对应 shm key（属跨模块协调，A 未擅自加）。
- ISP 参数寄存器由 C 在 `fpga_regmap.h` 的 ISP 块（0x10+）落地，A 只定义语义与范围。

### 3. 实车标定（上线前必须做）
以下阈值是“通用初值”，**拿到现场路口图/视频后应重新标定**：
- `traffic_light.c`：`TL_MIN_BRIGHT`(90) / `TL_MIN_AREA`(60) / `TL_REF_AREA`(600) / `TL_SAT_MIN`(0.25) / ROI 比例。
- `zebra_detect.c`：`ZEBRA_MIN_CONTRAST`(40) / `ZEBRA_MIN_STRIPES`(3) / `ZEBRA_MAX_STRIPES`(20) / ROI 比例。
- `lane_mark.c`：`LM_SOLID_MAX_GAP` / `LM_DASH_MIN_GAP` / `LM_CROSS_MARGIN` 等几何阈值。
- `turn_decide.c`：阈值取自 B 冻结的 `driving_config.h`（`LANE_STRAIGHT_TH=24`、`LANE_OFFSET_MAX=200`），A 只读不擅自改。

### 4. 运行方式
- **不连板子也能验证纯逻辑**：用 `--stub` 桩模式 + 8 套单元测试（本机/ WSL 均可）。
- **真实上板**：`make CROSS=aarch64-linux-gnu- bin`（需 B 的 `shm_ipc.c` + 板端 `librknnrt`）。运行时用 `--model <绝对路径>` 指定 RKNN 权重。

### 5. 红绿灯升级预案
若实车复杂光照（逆光/夜间）下纯 CV 不够稳，可升级为叠加一个 YOLOv2/YOLOv5 检测头（COCO 含 traffic light），**对外 `TrafficLightResult` 接口不变**。

### 5.3 感知模块实现 `perception/csrc/`
| 文件 | 干什么 | 关键逻辑 / 写了什么 |
|---|---|---|
| `pcie_capture.c` | 采集 + 纯算法 | 硬件通道仅在 Linux 编译（`PCIE_HW_UNAVAILABLE` 桩化）；`strip_leading_pixels` 剥 120 前导；RGB565↔888 按位展开/压缩；`save_rgb888_to_ppm` 调试存图 |
| `lane_detect.c` | YOLOPv2 分割 | `lane_model_extract`（不依赖 RKNN，可单测）；`lane_model_init` 读权重→`rknn_init`→查 IO 数/属性→分配缓存并**清零**（防尾部残留）；`lane_model_run` 最近邻缩放+推理+安全拷贝节点 0/1 |
| `turn_decide.c` | 弯道判定 | `lane_geometry_analyze` 8 带投影重心→远−近加权像素偏移；`turn_decide` 输出**真实置信度**（`有效带比例*60 + 覆盖率*400`，封顶100），覆盖不足判 `LANE_UNKNOWN`，阈值取 B 冻结配置 |
| `lane_mark.c` | 虚实线/变道 | 近场 ROI 左右半幅逐行查车道线像素→行出现率→断空率→虚实定性；取线**中心**（非外边缘）；近场线贴近中线判压线；`confidence` 两侧可见度加权 |
| `zebra_detect.c` | 斑马线 | 逐行水平灰度均值→亮度剖面；自适应阈值二值化；统计亮条纹段数（3–20 判斑马线）；纵向线被均值抹平不误报 |
| `traffic_light.c` | 红绿灯 | `tl_classify` 按归一化 RGB+饱和度+亮度判红/黄/绿；`max_blob` 显式栈 BFS 求最大连通块与包围盒；三色选面积最大且过阈值为点亮灯；**真实置信度**=面积/参考面积（封顶100） |
| `isp_params.c` | ISP 参数字典 | `DESC_TABLE` 14 项真值 + `isp_param_table` 指针表 + `lookup/clamp`。**本次修复 off-by-one**（见第二节） |
| `perception_pipeline.c` | 流水线编排 | `perception_step` 把 采集→转换→分割→判定 串起来；桩模式不碰硬件；每帧刷新 `lane_marks/zebra/tl` 并补同一帧号/时间戳；`frame_id++` 在时间戳前 |
| `lane_stub.c` | 感知桩 | `lane_stub_make_result` 吐确定直道结果，供 B 无硬件联调 |
| `main_perception.c` | 进程入口（板端） | 创建 `shm_lane`/`shm_pcie_img`；循环 `perception_step`→写共享内存；桩模式不写图像；日志输出线型/压线/斑马线/红绿灯 |

## 六、如何编译与运行

```bash
cd perception
make                 # 本机：编译全部源（零告警自检）+ 跑 8 套单测
make CROSS=aarch64-linux-gnu- bin   # 板端：交叉编译 perception_main（需 B 的 shm_ipc.c + 板端 librknnrt）
```

- 板端实跑：`perception_main [--stub] [--model <绝对路径>]`。
