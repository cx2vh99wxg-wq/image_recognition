转向脉冲标定、反馈闭环与保活设计（2026-10-31）

一、自动标定设计（独立设计页）

使用场景：车身固定，驱动断电或车轮可靠架空，MPU 随转向部件转动。
人工确认机械中位和当前 M session；软件不靠“收到 0 度”推定机械中位。
M 的 session 改变立即撤销旧参考，必须重新人工确认，禁止拼接角度。

状态：RESERVED → PREFLIGHT → MEASURE / REPOSITION → RETURN_NEAR_CENTER
      → COMPLETE / PARTIAL_COVERAGE / NO_MEASURED_MOTION；异常 → STOPPED。

时序：
  操作者       S 自动标定             M 角度流          S 短脉冲工具
  确认中位 ──→ 建立本 session 参考 ←─ 新鲜实测角度
               确认主车控已退出、SPI 独占、输出已释放
               收集静止基线      ←─ 100Hz STF1
               校验预测余量 ──────────────────────────→ 有效电平 ≤60ms
               监视断流/越界     ←─ 真实角度             到时释放左右
               等待角度稳定      ←─ 真实角度
               核对实际脉宽、会话、方向；写 A 试次和映射 JSON
               重复；必要时仅用已测映射移动到安全起点

默认时长：双向 5/10/15/17.5/18/20/25/30/40/50/60ms，每项两次。
每个脉冲前重新取得基线；至少 30 个连续样本，跨度 ≥400ms，角度极差
≤0.4°、角速度 ≤2°/s。源年龄加 S 本地持有时间须 <100ms；不假装测得
未同步双机的绝对网络传输延迟。CRC、序号、源时间或会话异常均拒绝。

预测范围采用 ±18°，给机械约 ±20° 留余量。未测响应仅允许保守探索；
无法安全预置或上界过大就跳过并记为覆盖不完整，不能强制测完 60ms。
软件脉宽超出请求 -0.05/+2ms 的试次不进模型，也不自动重放失败试次。

每次记录 requested_us、before/after/delta、实际软件脉宽、优先级、session、
源文件 SHA。保留零响应和响应离散程度，不强行拟合一条线性公式。
映射沿用 STEER_BENCH_RESPONSE_V1，按方向×时长×优先级聚合。
批次 JSON 持续原子写入并 fsync。A 试次用于标定，独立 T 目标试验不入表。
模拟批次带 simulation_only，禁止导出为真实运行模型。

二、车道实时闭环设计（独立设计页）

M 的车道模型、UDP 图像帧头、HMI 协议均不改。S 现有 UDP 程序继续发布
车道共享内存；FSPI 主进程增加可选择的闭环分支，并成为角度 UDP 的唯一
接收者。不能同时启动另一个占用 54321 的被动监视进程。

统一 IO：vehicle_control 主进程 → steering_runtime → controller → actuator
        → fspi_write_direction_once → FPGA reg2/reg3（0 有效、1 释放）。
所有本项目 SPI 工具使用 /tmp/steering-actuator.lock 独占；标定和整车互斥。

伪代码：
  验证模型、当前 session 的人工物理零点参考；失败则不启动自动转向。
  对新鲜且置信度 ≥60% 的新 NN 结果：
      直行目标=0；左/右目标=±min(目标限幅, road_angle×增益)。
      默认增益0.25、目标限幅12°；这两个参数不是机械标定结果。
      未知、S弯、异常、原 NN 结果超过500ms → 取消自动输出。
  tick：
      核对真实反馈、session、STOP、HMI 接管、FSPI 许可与机械包络。
      等待基线稳定 → 按真实响应分布反查脉冲 → 输出 → 到时释放。
      等待稳定 → 重新测量误差 → 到位或再次补偿。

反查同时限制最坏剩余误差和 E[|剩余误差|]，不把 0/6° 响应平均成
“准确转3°”。只用已测起始角附近的 cell，不做未验证外推。容差默认1°，
最多6个脉冲、一次反向修正；连续两次无进展、分辨率不足或超时即停止。
目标小幅抖动和重复帧不重置预算。闭环启用时完全绕开旧的固定长转向脉冲。

正常 tick 约0.5ms；有效脉冲期间避开原100ms慢策略扫描。STOP/人工转向
仍由 FPGA 原有优先级门控；S/R 可以清故障，不能给新 M session 授予零点。
实线禁止 HMI 变道的权限不被误当作“禁止沿弯曲车道行驶”。

启用方式：STEERING_CONTROL_MODE=closed-loop，另给已验证 TABLE 和当前
REFERENCE 文件。默认未设置时保持原模式；闭环请求失败不回退长脉冲。

三、保活设计（独立设计页）

在 S FSPI 主进程内使用 steering_keepalive，单调时钟周期1秒，不另开
竞争 SPI 的进程。读取 FPGA 状态并打印 STEER_HEARTBEAT，已有 reg5 权限
心跳继续沿用。M 静止 hold=1 时仍保持真实100Hz采样、序号和UDP心跳。

伪代码：
  if 台架标定中 or 正在发脉冲: 跳过本次心跳
  else if now >= next:
      只读校验控制快照，记录反馈有效性、角度、目标和状态
      next = now + 1秒（不补发积压心跳）
  读写故障 / 反馈超时: 不生成新的转向脉冲

互斥由统一 SPI owner 和单线程调度保证；心跳不发 GO/BACK、SPEED、
STOP 或左右转向脉冲，因此不改变标定结果和人工行驶状态。

必须区分：程序/链路保活 ≠ 已证明能阻止遥控器/小车自身休眠。
目前接口只有实体按键模拟，没有已确认的无动作 RF 唤醒协议；极短转向
脉冲可能有零响应，也可能突然转动，不能作为“保证不动”的保活。
本实现不自动周期按键。若小车会自行休眠，需要先确认其真正超时来源，
再验证无动作唤醒命令；现阶段不能声称物理休眠问题已解决。

四、与任务描述的实际差异

1. 原 S steering_feedback.c 也是 NOT_READY 空实现，本轮补齐真实接收。
2. vehicle_control(command, enable) 实际在 S/fspi/csrc/fspi_module.c；
   主策略循环在 S/fspi/csrc/main.c。本轮在主循环统一集成，保留旧函数。
3. 原固定脉冲以0.4～1.5秒等时长操作，并不是测角闭环。本轮新增路径
   单次严格请求≤60ms；原 actuator 硬上限1000ms保留以兼容旧工具。
4. M 测角与48字节 STF1 契约已经可用，因此不重复修改 IMU 滤波或重启
   M 服务。只同步 M 反馈说明和只读健康检查工具，保留当前 session。
5. C 不引入 JSON 库：由受校验的 V1 JSON 导出 STEER_RESPONSE_TABLE_V1
   文本表，保存 JSON/表 SHA；运行时校验表结构和原始响应统计。
6. Linux 软件定时并非硬实时；SIGTERM、普通错误路径尝试释放。
   SIGKILL、内核崩溃、SPI完全失联后的硬截止需要 FPGA 看门狗支持，
   本轮没有修改 FPGA，不能由用户态保证这种故障下的物理释放。
7. 单个方向盘 IMU 无法分离车身偏航和方向盘相对车身的转角；本轮固定
   车身测试通过，也不等同于整车行驶时的测角精度验收。

五、实施步骤与验收清单

阶段1 源码与编译：
  [已通过] Windows build.py --test：边界、状态机、超时、会话、模拟隔离。
  [已通过] S 板本机 ARM 编译：工具、控制器、接收器、FSPI主程序。
  [已通过] 假 IO 集成：车道目标映射、重复目标、断流、S/R与STOP。
  [已通过] 原 FSPI 回归：行人/AUTO、车道、实线权限、红灯、档位、协议。
  [已通过] 新 SPI owner 测试：不触碰真实设备，验证独占和失败释放锁。

阶段2 实机标定（必须在新的物理零点确认后）：
  - 确认固定、供电、方向盘中位、MPU安装与当前session。
  - 停主车控和54321旧监视器，检查SPI无人占用，建立bench标记。
  - steering_reference.py 采集当前session参考；只认人工物理中位。
  - steering_auto_calibrate.py 自动测量，持续观察每次日志与释放结果。
  - 两方向有足够非零响应；缺失时长、时序异常、未回中必须明确列出。
  - 独立目标0/±5/±10/±15°按实际已覆盖范围验证，不混入标定集。
  - 记录命中±1°比例、误差最大值、响应重复性、脉宽偏差和总耗时。

阶段3 接整车：
  - 仅使用实测、非模拟且覆盖合格的映射；确认同一M session参考。
  - 先台架测试 STOP、人工接管、断流、新session、S/R，确认撤销。
  - 再显式开启闭环，检查STEER_LANE/STATE/HEARTBEAT，杜绝旧脉冲重复。
  - HMI方向、前后锁存、S/R、调速、行人刹停、红灯GO、实线红叉均回归。
  - 最后才在低档、现场可接管条件下验证道路目标增益与限幅。
