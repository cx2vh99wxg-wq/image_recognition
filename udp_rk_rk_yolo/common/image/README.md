# 摄像头传输边界：末行黑白闪点回归规则

目前板上 FPGA 的 640×480 四宫格由 320×240 图块组成。在**原始 DMA 坐标**中，每格有以下无效传输区域：左侧 8 列、倒数第二行右半边、最后一整行。

`camera_valid_rows.h` 在旋转、镜像、相机格重排、畸变校正、推理和发布之前统一延拓边缘。必须先用上一有效行修复倒数第二行右半边，再填充最后一行。不得从相邻摄像头取像素，不改变分辨率或标定坐标。

2026-11-09 复发原因：旧版仅在黑白像素占比 ≥90% 时修复倒数第二行；真实故障帧只有 122/160、142/160 个极值像素，剩余为混合数据，所以漏检。**该区域是否有效由传输格式决定，不得再用颜色比例或闪烁检测决定是否修复。** 即使出现全黑、全白或普通颜色的旧数据，也必须延拓。

修改采集、图像边界、旋转、拼接或像素转换后必须：

1. 执行 M/pcie 的 `make test-camera-guard`（正常 `make all` 已自动执行）；检查部分黑白、随机旧数据、四格边界、有效像素不变、重复执行和内存边界。
2. 执行 S/x11/csrc 的 `make test-camera-guard`，核对旋转后六宫格边界（正常 `make all` 也自动执行）。
3. 在板上连续采集原始处理后画面及实际发布画面，逐格检查最后两行；记录实际帧率。M/pcie 的 `make camera-edge-probe` 可构建只读检查工具，运行 `./build/camera_edge_probe 60` 连续检查 60 秒。单张截图不能证明间歇闪点已消失。
4. 核对运行二进制与部署文件校验值，并验证重新启动后的程序。保留 DMA 读回等待和完整帧退出逻辑；不得为了提速直接缩短等待或强杀半帧中的采集进程。

以上边界契约针对当前已验证 FPGA 数据格式。更换 FPGA 数据流后，应重新测量有效区域并同步更新测试，不能直接套用。

2026-11-09 M 板验收：修复前 8 秒发布 241 帧，其中 218 帧检出异常边界；修复后 60 秒采样 1,801 帧，异常边界、黑白闪点、共享内存读取错误均为 0，发布速率 30.00 帧/秒。另取 6 帧 NN 原始输入，四格末尾区域全部通过，并读取实际 X11 窗口确认显示正常。新回归在旧实现上触发断言，在新实现上通过。
