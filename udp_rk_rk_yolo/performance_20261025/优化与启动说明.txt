保留的优化
----------
1. M采集、发布和识别解耦：单识别工作线程，单个可替换待处理帧，持续发布最新视频；模型推理次数单独统计。默认目标30 FPS，仍使用原模型和每3次采集提交策略。
2. 车道mask使用不可变结果快照；传输真实识别源帧号和输入年龄，500ms过期后置信度置零，旧结果不会随视频刷新伪装成新结果。
3. UDP V3按行打包：每帧480包、单包1344字节，32包批处理；默认200Mbps节奏，固定双帧重组，完整帧校验后才发布最新帧。保留旧协议视频兼容；旧流缺少真实NN身份时不发布有效车道置信度。
4. 图像共享内存完整快照互斥保护，取消读端10ms等待和逐帧日志，修复root/linaro信号量权限；图像共享头104字节及RGB565帧格式保持不变。M发送端支持采集进程重启后重新连接图像、锁和车道数据。
5. S预处理和告警绘制做等价优化：保持混色、闪烁和叠加顺序，跳过必为零强度的区域。S行人检测、两秒有效无人确认和人工REARM的控制流程保持原流程。
6. M本地预览启用MIT-SHM并安全回退。S默认保留稳定的XRender+MIT-SHM完整同步显示；原界面、640×480源图和2560×1440显示模式保留。

上下抖动和定格修复
------------------
默认不再自动启用新GLES显示路径，也不默认启用局部上传或异步SHM完成事件。ConfigureNotify、Destroy和输入事件只处理主窗口，避免辅助窗口事件影响画面尺寸。
图像读端每秒检查当前共享段及writer状态；断开或换代时释放旧映射/信号量并重新连接，源帧号从1重新开始也能恢复。
显示模式、行人报警显示和车道元数据均支持晚启动、换代重新连接；未初始化时不调用getter，避免每毫秒错误日志刷屏导致阻塞。
实时模式不自动进入离线预览。缺少采集/接收进程时不会产生新的实时帧，需要恢复完整S端链路。只有新帧通过校验后才更新在线时间和输入计数。
现场已恢复完整链路，用户确认实时更新且不抖动；最终修复也已编译上板。

重新启动
----------
当前两端均已运行，无需立即重启。
重新上电后先启动M，再启动S。分别在板卡终端执行：

M端：
  cd /home/linaro/M
  make stop
  make -j2
  make run

S端：
  cd /home/linaro/S
  make stop
  make -j2
  make run

make run负责完整启动；只运行显示程序不会启动采集、UDP接收和FSPI。
通过S端make run启动时，退出主窗口会执行整套S端清理；需要恢复时重新启动完整S端。
本轮为ARM软件更新，FPGA RTL和位流没有在本轮修改。DMA固定为匹配现有RTL的单行请求，不能直接将DMA_ROWS设为2。
