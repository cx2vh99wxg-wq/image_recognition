# 弯道控制不执行问题排查指南

## 问题现象
UDP日志显示识别到了左右转，但FSPI没有执行转向控制，方向盘没有动作。

## 排查步骤

### 步骤1：重新编译FSPI程序

```bash
cd S/fspi
make clean
make
```

### 步骤2：确认启动顺序

**必须按此顺序启动：**

```bash
# 终端1: 启动UDP接收程序
cd S/udp
./app

# 等待看到 "弯道检测共享内存初始化成功" 的提示

# 终端2: 启动FSPI控制程序
cd S/fspi
sudo ./app
```

### 步骤3：查看FSPI启动日志

FSPI启动时应该看到：

```
=== 弯道检测共享内存初始化 ===
弯道检测共享内存初始化成功，FSPI将读取UDP传来的弯道信息
```

**如果看到：**
```
弯道检测共享内存初始化失败！
注意: 这可能是因为UDP程序尚未启动
```

**原因：** UDP程序未启动或共享内存未创建
**解决：** 先启动UDP程序，再启动FSPI程序

---

### 步骤4：查看弯道检测读取日志

每1秒应该看到类似这样的日志：

```
[调试] 弯道检测读取成功:
  帧ID: 1234
  弯道类型: 1 (0=直道,1=左弯,2=右弯,3=S弯)
  置信度: 85%
  角度: 30°
  上次弯道类型: 0
  当前左转状态: 0, 右转状态: 0
```

**情况A: 看到 "弯道检测共享内存读取失败"**
```
⚠️  弯道检测共享内存读取失败 (失败次数: 50)
   可能原因: UDP程序未启动或共享内存未初始化
```

**原因：**
- UDP程序未启动
- UDP程序已崩溃
- 共享内存被删除

**解决：**
```bash
# 检查UDP程序是否在运行
ps aux | grep app

# 检查共享内存是否存在
ipcs -m | grep 1234567e
```

**情况B: 完全没有读取日志**

**原因：** 主循环未执行弯道检测代码
**解决：** 检查代码是否被编译进去，重新make

---

### 步骤5：查看should_update判断日志

```
  should_update判断: 1
  条件1 (类型变化): 1 != 0 = 1
  条件2 (置信度变化>20): |85 - 0| = 85 > 20 = 1
```

**如果should_update = 0：**

原因是弯道类型没有变化且置信度变化<20%

**这是正常的！** 只有弯道类型变化时才会执行控制

---

### 步骤6：查看置信度判断日志

当检测到左弯或右弯时，会打印：

```
[调试] 检测到左弯:
  置信度: 45% (阈值: 60%)
  是否满足阈值: 否
   ⚠️  置信度较低 (45%)，暂不执行转向
```

**如果置信度<60%：**

这是**最常见的原因**！

**解决方案A：** 提高M端检测准确度

**解决方案B：** 临时降低置信度阈值（测试用）

编辑 `S/fspi/csrc/main.c`：

```c
// 第603行和648行，将60改成30或更低
if (curve_confidence >= 30) {  // 原来是60
```

然后重新编译：
```bash
cd S/fspi
make clean
make
sudo ./app
```

---

### 步骤7：查看vehicle_control调用日志

如果置信度足够，会看到：

```
  [调试] 置信度足够，准备执行左转控制
   ⚡ 启动左转 (置信度: 85%, 角度: 30°)
   [调试] 调用 vehicle_control(2, 1) 启动左转
正在运动 左转...
调试信息: 命令=2, enable=1, 地址=0x0002, 发送值=0
车辆控制成功: 左转 运动 (地址=0x0002, 值=0)
   [调试] vehicle_control返回: 0
   ✓ 左转已激活
```

**如果没有看到这些日志：**

检查前面的步骤，问题在更早的环节

**如果看到 "vehicle_control返回: -1"：**

```
   [调试] vehicle_control返回: -1
   ✗ 左转启动失败
```

**原因：** FSPI硬件通信失败

**解决：**
1. 检查SPI设备：`ls -l /dev/spidev4.0`
2. 检查权限：确保用sudo运行
3. 检查硬件连接

## 快速诊断命令

### 1. 检查共享内存是否存在
```bash
ipcs -m | grep 1234567
```

应该看到：
```
0x1234567a ...    # UDP图像共享内存
0x1234567e ...    # 弯道检测共享内存
```

### 2. 检查进程是否运行
```bash
ps aux | grep app
```

应该看到UDP和FSPI两个进程

### 3. 实时监控日志
```bash
# UDP端
cd S/udp
./app 2>&1 | grep "弯道"

# FSPI端
cd S/fspi
sudo ./app 2>&1 | grep "调试"
```

## 常见问题汇总

### 问题1: FSPI启动时共享内存初始化失败

**症状：**
```
弯道检测共享内存初始化失败！
```

**原因：** UDP程序未启动
**解决：** 先启动UDP，再启动FSPI

---

### 问题2: 读取失败

**症状：**
```
⚠️  弯道检测共享内存读取失败 (失败次数: 50)
```

**原因：**
1. UDP程序未启动
2. UDP程序崩溃了
3. 共享内存被意外删除

**解决：**
```bash
# 重启UDP程序
cd S/udp
./app

# 等几秒后再重启FSPI
cd S/fspi
sudo ./app
```

---

### 问题3: 置信度不够

**症状：**
```
  置信度: 45% (阈值: 60%)
  是否满足阈值: 否
   ⚠️  置信度较低 (45%)，暂不执行转向
```

**这是最常见的原因！**

**解决方案：**

**方案A（推荐）：** 提高M端检测准确度
- 优化弯道检测算法
- 改善光照条件
- 调整摄像头角度

**方案B（临时测试）：** 降低阈值

编辑 `S/fspi/csrc/main.c` 第603行和648行：
```c
if (curve_confidence >= 30) {  // 改成30或更低
```

重新编译：
```bash
cd S/fspi
make clean
make
sudo ./app
```

---

### 问题4: 没有调用vehicle_control

**症状：** 置信度够了，但没有看到 "调用 vehicle_control" 的日志

**原因：**
1. should_update = 0（弯道类型没变化）
2. left_turn_active 或 right_turn_active 已经是1

**解决：**
- 第1种情况是正常的，等待弯道类型变化
- 第2种情况也是正常的，说明转向已经激活

---

**症状：**
```
   [调试] vehicle_control返回: -1
   ✗ 左转启动失败
```

**原因：** FSPI硬件通信失败

**检查：**

# 2. 是否用sudo运行
# 必须: sudo ./app

# 3. 查看FSPI初始化日志
# 应该看到: FSPI初始化成功！
