# 带真实角度反馈的单次台架测量

`steering_bench.py`同时运行已经独立测试的C接收器和C脉冲工具。只用于有人观察、固定车身的台架，原整车控制API仍为NOT_READY。它不启动视觉转向，不自动回零，不宣称机械中位，也不在串口超时后补发或重试。

每次先检查台架保护标记、旧车控退出、SPI无其他所有者及FPGA门控，再获得连续静置角度基线。M的反馈必须真实、新鲜且与本次零点的会话一致。会话变化、断流、过期、非真实数据或超出试验范围时终止，仍在运行的脉冲进程接收SIGTERM并由C工具释放。每次试验ID会先独占预留，失败后也不允许重复使用。

接收时刻来自S的C接收器单调时钟，可与同一S板的脉冲软件计时比较；M和S时钟不直接相减。源年龄加S持有时间不包含未知网络传输耗时，不能据此声称已测量绝对网络延迟。CSV记录的是相对角度估计和软件写入窗口，实际引脚低电平波形和独立角度精度尚未由此验收。

当前初始计划为单次不超过20000us、观测角度相对标记零点不超过±10°。发脉冲前还用保守步长检查预计余量；该步长是试验假设，不是机械最大步长的保证。观测越界才取消无法替代机械限位，尤其当一个最小脉冲本身跨过目标时，不能无限缩短时长或反复左右振荡。

现场确认物理标记零点、左正右负之后，把该时刻的M会话和原始角度作为本轮参考；M重新启动或手动重新置零导致会话改变后，该参考作废。以下参数仅对应2026-10-30本轮已确认的参考，不作为重启后的默认值：

```sh
cd /home/linaro/S/steering
python3 tools/calibration/steering_bench.py --trial A027_left_17750us --direction left --duration-us 17750 --reference-session 95601018 --zero-raw-deg 0.151
```

`logs/<trial>.json`保存基线、稳定终值、增量、软件实际间隔和状态。另存完整接收CSV/日志、脉冲CSV/日志以及不能重复使用的reservation文件。完成一次后，先核对实物动作与记录，再决定下一次；不要把上述例子改成无人观察的自动循环。

细化请求时长前先检查实际软件间隔的抖动；输入1us并不代表物理脉冲准确到1us。左右、换向和同向、初始角度及重复次数需要分别记录；拟合只在实测区间内使用，不能把两个点强制拟合成过原点的线性函数。

## 阶段三台架目标角度原型

`response_model.py`保留无动作样本，按左右、请求时长和调度设置分组，输出均值、中位数、观察范围、响应次数及起点范围。它提供经验响应表，不宣称存在精确的单值函数，也不把输入微秒分度当作角度分辨率。

`steering_target.py`输入相对标记零点的目标总角度：目标+5°表示到左侧5°，不表示在当前位置再向左5°。每步重新获取真实反馈、选择实测过的脉冲、等待稳定，再计算剩余误差。模型以至少2次样本作为初期实验入口，不是可靠性验收；优先选择观察范围内不会明显放大剩余误差的动作。默认只允许±8°目标、±10°观测范围、最多4次脉冲和一次换向，连续两次无进展退出。返回REACHED才表示本次稳定测量值落在指定容差内；RESOLUTION_LIMIT、INSUFFICIENT_MODEL、NO_PROGRESS等均不表示到位。

```sh
python3 tools/calibration/response_model.py --logs logs --output logs/response_model_001.json
python3 tools/calibration/steering_target.py --trial T001 --target-deg 3 --tolerance-deg 1 --model logs/response_model_001.json --reference-session 95601018 --zero-raw-deg 0.151
```

上述会话和零点仅对应本轮台架。程序不会在启动时重新假定当前位置为0，也不授予机械ZERO_VALID。正式C控制API、现有整车进程和视觉控制入口仍未启用；台架原型不替代车辆运动时的车身旋转补偿与统一FSPI控制权设计。

`--realtime-priority 10`仅作为调度对照组。当前已有实时组无响应、普通组有响应的样本，但尚不能据此断言原因；模型分开保存两个组，阶段三默认使用普通调度，不能混用两组后宣称一种精度。

A053请求17.75ms，软件记录28.898ms；分解得到等待到释放开始28.804ms、释放写入0.095ms，表明该次主要是截止唤醒延迟。这条原始记录完整保留，但模型排除计时偏离请求超过-0.05/+2ms的样本；记录器之后发现此类偏离会返回TIMING_FAULT并停止序列。该检查在事后识别软件计时异常，不能替代硬件定时器保证引脚宽度。CPU输入分度、软件计时和物理输出宽度需继续分别看待。

模型使用每个样本的剩余绝对误差求均值。不能把“一半不动、一半转6°”平均成“可控地转3°”。目标试验T系列不进入A系列模型拟合，便于保留独立验证结果。

## 大角度与连续时长标定

默认仍为20ms、±10°观测范围和±8°目标。大角度阶段必须显式传入`--angle-limit-deg 18 --request-limit-us 60000`；目标程序另加`--target-limit-deg 15`才允许本轮±15°目标。绝对软件上限为60ms请求和±18°观测范围，保留到用户报告约±20°机械端点的余量，不自动寻找或顶住机械限位。

连续30/40/60ms脉冲需从反侧起点开始、给出保守预估行程余量，不能从17～20ms的小步数据直接外推出“15°对应固定毫秒数”。`validate_pulse`会同时检查当前角度与预计端点。时间表必须记录起点、左右方向、同向/换向及无响应，不把多个短脉冲的总时长当作等价的单个连续长脉冲。

M换会话后必须重新采集静置参考。仅当操作者明确确认回到了原物理标记零点再置零，才可用`--reference-binding`显式关联新会话与原标定数据；模型保留各样本的真实会话号，并核对当前会话、原始零点偏移和已确认会话集合。不自动把任意重启后的当前位置当作原零点。
