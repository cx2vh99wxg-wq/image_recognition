# A：独立脉冲测试

## 操作

在 `S/steering` 中构建：

```sh
python3 tools/build.py
./actuator/build/steering_step --direction left --duration-ms 20
./actuator/build/steering_step --direction right --duration-ms 40 --repeat 3 --gap-ms 1000
```

默认只输出 DRY RUN。Windows 使用 `python` 和对应 `.exe`。

真实 S 端 Linux/RK 构建与运行：

```sh
python3 tools/build.py --hardware
mkdir -p logs
sudo ./actuator/build/steering_step_fspi --backend fspi --direction left --duration-ms 20 --csv logs/A_left_20ms_001.csv
sudo ./actuator/build/steering_step_fspi --backend fspi --direction release
sudo ./actuator/build/steering_status
```

CSV 必须指定新文件名，不覆盖旧记录。完整选项通过 `--help` 查看。
默认单次 1 个脉冲、最大 200ms；显式 `--max-pulse-ms` 可调整，但硬上限为 1000ms。
先验证小脉冲，不要因看不到动作就直接放大到机械限位。

## 电平与退出

- LEFT：先释放右 reg3=1，再请求左 reg2=0；RIGHT 相反。
- 每次动作前释放两侧，到截止时间或正常取消时释放两侧。
- 只写寄存器 2/3，不写 GO、BACK、STOP，不清除已有 STOP 锁存。
- Ctrl+C/SIGTERM 只在处理流程中撤销输出；进程被强杀、设备失联或掉电不能依靠软件释放。
- 当前没有新增 FPGA 最大脉冲超时。下地前需要独立的超时/停止保障。
- 硬件锁只约束本工具的其他实例，旧 `vehicle_control` 不遵守这个锁。
  真实测试前必须退出旧自动控制程序，固定车辆，保留可操作的物理 STOP。
- FPGA 仍可能通过 STOP、人工接管等门控拒绝请求；写事务成功不等于方向盘运动。

## 先测什么

1. 用物理标记确认初始角度，短脉冲后观察释放即刻、0.5s、2s 的角度。
2. 判断松开后保持还是自动回中；这由机构决定，不是路面算法参数。
3. 在安全范围内逐步改变时长，分别重复左/右动作，并记录反向回差。
4. 使用量角器/固定指针/独立视频刻度测角，逻辑分析仪测实际触点低电平时长。
5. 重复脉冲会累积转角；程序不会自动回中。每次要么记录真实起点，要么人工重置起点。

## CSV 的边界

记录请求时长，以及 enable/release 写调用的开始和返回时刻。
`software_elapsed_ms` 是释放返回与使能返回之间的时间，含部分通信耗时。
这些值都不是实际引脚波形，更不是角度反馈；实际边沿位于写调用的时间窗口内。
操作系统调度、驱动重试会拉长时间，工具不能承诺硬实时。

请另行记录物理初始/终止角、电池状态、负载、是否反向，以及实际波形时长。

## DEBUG 联调与源码同步

本次连接最初为 COM12，重连后曾为 COM13，参数为 1500000、8N1；脚本要求显式指定端口，先核对板卡身份。
`debug_serial.ps1` 执行明确指定的板端脚本，`upload_debug.ps1` 只传送经逐块和整包 SHA256 校验的暂存文件，不自动启动它。
本分支修改 S 相关 C/C++ 后，应同步对应头文件/构建依赖到 `/home/linaro/S`，保存板端旧版并核对哈希，在板上编译后再测试。共同依赖在 `/home/linaro/common/steering`；不上传 M 的实现。
DEBUG 使用内核 IRQ/FIQ 调试器，异常 BREAK 可打断传输；接收器仅在整包校验通过后形成正式暂存文件。上传失败不能继续安装。命令执行前另校验脚本文本 SHA256，超时不自动重试运动命令。
命令脚本先将 Windows CRLF 统一为 Linux LF，再对实际发送文本计算校验；源码上传保持原始文件字节。

`steering_status` 是 RX-only 逻辑快照诊断，不写控制寄存器。也须先退出其他 FSPI 使用者，避免切换 SPI 配置的竞争。
它会显示 STOP、FS_ARMED、RESET、HMI、左右触点等；不支持扩展快照的位流明确报错，不伪造状态。
硬件脉冲工具现在还会在有效期间读取一次扩展快照，打印 `FPGA_ACTIVE`。请求侧未低、对侧未释放、前后驱动有效或 STOP/布防状态异常时立即撤销请求并返回失败；读取失败也撤销。
这次读取计入原脉冲期限，不重新开始计时；系统调用阻塞仍可能使实际释放变晚。逻辑触点确认不等于电压/遥控链路/机械动作确认。
硬件工具使用 `CLOCK_MONOTONIC` 的绝对截止时刻等待，避免1ms轮询本身的量化超时；Ctrl+C/SIGTERM可打断等待并释放。Linux调度和SPI写入仍有延迟，仍以CSV写调用窗口和独立波形测量为依据，不承诺硬实时。
可使用 `--duration-us 17500` 请求17.5ms，与 `--duration-ms` 互斥。原毫秒接口保留；CSV的 `requested_ms` 统一保留三位小数。微秒是输入分辨率，不代表微秒级电平精度。
FS_ARMED 未置位、STOP 有效或仍有人工转向请求时，先排查门控，不通过加长脉冲判断机械死区。

初测每次只发一个脉冲，由人报告实际角度后才决定下一次。本轮 10ms 无可见动作，两次20ms后累计目测已约左30°（左侧行程估计约60°），因此当前将单次请求限定为 `--max-pulse-ms 20`，不继续向40/80ms放大。
建立最小有效时长后，要在同一起点分别重复至少三次，再测相反方向和换向回差。不同起点累计测试不能直接比较成左右差异。
每次记录起始角、释放后尽快读得的角度、0.5s/2s 角度及观测分辨率。肉眼最早读数不能当作精准的释放瞬间。
本轮操作者已说明角度主要凭感觉，历史角度只保留为粗略口述，不能据此拟合时间—角度函数。17.5ms的小幅动作尚未稳定复现；后续须先增加固定刻度/指针并给出可分辨范围，不能靠继续细分输入时间替代实际量角。
结果记录见 [A_BENCH_20261029.md](A_BENCH_20261029.md)。

## 用固定交点人工量角

在轴心建立固定坐标系。车身上固定x=-b的竖线和尺子，转动部件上的直标线须经过轴心并刚性随轴转动；当前操作者实际使用b=40mm。测其延长线与固定竖线的交点，不是测一个随动点；测量平面须与转动标线平行并尽量共面，观察方向正对该平面。

本轮零位标线水平、y0=0。操作者只报告交点纵坐标绝对值m及“当前位置在零点左侧/右侧/零点”，无须判断y轴正负。注意位置侧别不是上一次动作方向：向右回了一下但尚未越过零点时，仍须报告“零点左侧”。

在同一反正切分支内，左侧角度为`+atan(m/b)*180/pi`，右侧为负值。脉冲增量为动作后角度减去动作前角度，不能直接对两个纵坐标绝对值之差求反正切。标线不能跨过竖直方向；若零位本身不水平，绝对值加位置侧别的信息不足，须重新建立水平零线或使用下述有符号读数模式。

```sh
# A019人工读数：实际基线40mm、交点纵坐标绝对值约3mm、当前位置在零点左侧
python3 tools/actuator/angle_from_line.py --baseline-mm 40 --abs-y-mm 3 --position-side left
# 其他零位布置可使用有符号读数；以下仅为计算示例，须先实测LEFT使y向上增加
python3 tools/actuator/angle_from_line.py --baseline-mm 40 --zero-y-mm 0 --y-mm 3 --left-y-sign up
```

基线必须显式输入，避免将当前40mm误按早先计划的80mm换算。共同接口始终为转向LEFT正/RIGHT负；当前40mm基线在零位附近1mm约对应1.43°，实际精度取决于尺子、轴心定位和视差。A019计算值约4.289°只宜按约4°的人工测量解读，不能将显示小数位当作测量精度。

有符号模式中y向上为正，几何逆时针角差为`[atan(-y/b)-atan(-y0/b)]*180/pi`，LEFT到y符号的映射须独立确认。每次保留实际基线、原始读数、零位、当前位置侧别和可分辨范围，不只记录换算角度。工具不访问硬件、不控制小车，也不改变A018之前的粗略观察。

## 防止整车程序在观察间隙重启

独立台架会话使用 `/tmp/steering-bench.active` 标记，并正常退出现有 `vehicle_control`。
新版 `vehicle_control` 在此标记存在时，以 75 退出，检查发生在任何 SPI 初始化/写入之前。
因此桌面再次执行 `make run` 时也不会恢复自动转向；这期间软件监控和显示状态更新仍处于暂停状态。
台架测试结束后，由操作者明确结束本轮，移除此标记再恢复整车程序。测试暂停等待观测时保留标记，避免把等待误认为结束。
恢复正常控制前还须确认实际转向位置；旧程序中的 NEUTRAL 状态不能证明机构已回中。
此标记只约束新版旧车控入口，不替代 FPGA STOP 或物理断电。
